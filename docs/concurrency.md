# Concurrency

The concurrency model intentionally avoids lock-free data structures in favor of a simpler, highly optimized `std::mutex` + `std::condition_variable` bounded queue.

## Producer-Consumer Model
- **Producers**: Network threads receiving orders from clients.
- **Consumer**: A single thread running the matching engine logic.

## Mutex Usage
A single `std::mutex` guards the queue. Contention is minimized by keeping the critical section (the `push` and `pop` operations) extremely short.

## Sequence Numbering
While the current implementation uses the arrival time in the queue (or timestamp generated by the producer), a strict monotonic sequence number can be added at the queue's entry point to resolve sub-millisecond arrival ambiguities.

## Why Order Book State is Single-Owner
If multiple threads mutated the order book concurrently, we would need fine-grained locks on price levels. This causes high cache coherency traffic and false sharing. By funneling updates through an MPSC queue, the matching engine stays entirely in the L1/L2 cache of its dedicated core, drastically reducing matching latency.
